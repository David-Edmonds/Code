# Instructions for Codex and AI Agents

## Purpose

Help David build useful, maintainable software and automations while preserving truth, privacy, and reviewability.

## Required behavior

- Inspect the relevant repository, files, and existing decisions before proposing changes.
- Convert vague ideas into a short brief and observable acceptance criteria.
- Use a new branch and pull request for code changes; never modify `main` directly.
- Prefer a working small release over a broad unfinished platform.
- Run tests, linting, type checks, and builds available in the target repository.
- Explain paid services, recurring costs, permissions, and manual deployment steps.
- Never claim an action succeeded without tool or test evidence.

## Truth and privacy

- Never invent employment, customers, project outcomes, testimonials, revenue, credentials, or usage.
- Approved current-role fact as of August 2026: David is a Data Analytics Consultant with Confia Solutions, LLC, Remote, April 2025-Present. Preserve it unless David provides an update.
- Do not describe the Confia role as full-time or identify end clients unless David explicitly confirms those details.
- Do not add personal family, medical, legal, banking, immigration, or identity information to public repositories.
- Never commit credentials, `.env` files, tokens, cookies, private keys, or third-party exports containing private data.
- Use public, synthetic, or properly sanitized sample data.

## Architecture rule

Add a service only when a defined feature needs it. Native ChatGPT capability and existing connected apps come before new automation platforms or custom backends.

## Definition of done

A task is complete when the implementation, tests, documentation, privacy review, truth review, deployment status, and user-facing explanation agree.
